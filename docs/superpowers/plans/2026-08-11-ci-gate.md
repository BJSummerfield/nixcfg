# CI Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the three auto-upgrading hosts deploy only commits that have been evaluated successfully, without changing how commits reach `main`.

**Architecture:** `flake.nix` grows a check per configuration, so `nix flake check` evaluates every host. A GitHub Actions workflow runs that check and, on a green push to `main`, fast-forwards a `verified` branch. The hosts' `system.autoUpgrade` tracks `verified` instead of `main`, so a broken push simply fails to advance the ref and the hosts hold their last good generation.

**Tech Stack:** Nix flakes, GitHub Actions (`ubuntu-latest`), `actions/checkout@v7`, `cachix/install-nix-action@v31`.

## Global Constraints

- All five NixOS hosts are `x86_64-linux`, and `darwinConfigurations.mac` evaluates on Linux. Everything lives in `checks.x86_64-linux`; do **not** add a macOS runner or a second system.
- Checks evaluate only. Never build a host's `toplevel` in CI.
- `actions/checkout` must set `fetch-depth: 0`. A shallow clone cannot push, and the ref-advance step is the whole point of the workflow.
- The `verified` push must **not** be forced. A rejected non-fast-forward is the desired behaviour after a force-push to `main`.
- The `verified` branch must exist on the remote **before** the `autoUpgrade` change reaches the hosts, or all three auto-upgrades fail on an unresolvable flake ref. Task 3 comes before Task 4 for this reason.
- The repo is formatted with nixfmt. After editing any `.nix` file, run `nix fmt` and include the result in the same commit.
- `nix flake check` takes several minutes on a cold store. Give it a generous timeout rather than killing it.

```nix
      # Evaluation-only. `nix flake check` builds nothing beyond one empty
      # marker derivation per configuration; the work is forcing the eval.
      # Everything lives under x86_64-linux because all five NixOS hosts are
      # x86_64-linux and the darwin config evaluates here too. Generated
      # rather than listed so a host added later is checked automatically.
      checks.x86_64-linux =
        let
          pkgs = nixpkgs.legacyPackages.x86_64-linux;
          # drvPath forces a full evaluation without building anything.
          evalOnly =
            name: drv: builtins.seq drv (pkgs.runCommand "eval-${name}" { } "touch $out");
          evalAll =
            prefix:
            nixpkgs.lib.mapAttrs' (
              name: cfg:
              nixpkgs.lib.nameValuePair "${prefix}-${name}" (
                evalOnly "${prefix}-${name}" cfg.config.system.build.toplevel.drvPath
              )
            );
        in
        evalAll "nixos" inputs.self.nixosConfigurations
        // evalAll "darwin" inputs.self.darwinConfigurations
        // {
          devboxes = import ./tests/devboxes.nix {
            inherit nixpkgs inputs;
            system = "x86_64-linux";
          };
        };
```

### Task 2: Add the workflow

**Files:**
- Create: `.github/workflows/check.yml`

**Interfaces:**
- Consumes: the seven checks from Task 1, via `nix flake check`.
- Produces: on a green push to `main`, fast-forwards `refs/heads/verified` to that commit. Task 4's `autoUpgrade.flake` depends on that ref existing and moving.

- [ ] **Step 1: Create the workflow file**

Create `.github/workflows/check.yml`:

```yaml
name: check

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: write          # needed only by the ref-advance step

concurrency:               # serialize, so two quick pushes cannot race the ref
  group: verified
  cancel-in-progress: false

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0   # a shallow clone cannot push: "shallow update not allowed"

      - uses: cachix/install-nix-action@v31

      - run: nix flake check --print-build-logs

      # Not forced: after a force-push to main this is rejected as a
      # non-fast-forward and the run goes red, rather than moving the hosts
      # onto rewritten history.
      - name: Advance verified
        if: github.event_name == 'push'
        run: git push origin HEAD:verified
```

- [ ] **Step 2: Lint the workflow**

GitHub will not tell you about a syntax error until you push, so check locally:

```bash
nix run nixpkgs#actionlint -- .github/workflows/check.yml
```
Expected: no output, exit 0.

- [ ] **Step 3: Verify the two load-bearing details survived**

```bash
grep -n 'fetch-depth: 0' .github/workflows/check.yml
grep -n 'contents: write' .github/workflows/check.yml
grep -c 'force' .github/workflows/check.yml
```
Expected: the first two each print a matching line; the third prints `0` — no force-push anywhere.

- [ ] **Step 4: Commit**

```bash
git add .github/workflows/check.yml
git commit -m "feat(ci): run nix flake check, advance verified on green

Gates on a ref rather than on branch protection: most commits reach main
by direct push, so a PR-only gate would miss them. A red run leaves
verified where it is."
```
