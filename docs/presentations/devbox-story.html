A field report from my homelab

Planning with Claude, coding in a box

How one grab at ~/.ssh turned into isolated agent containers on a server — and why the code never leaves the box.

The incident

The agent runs as you

Claude Code, running on my laptop, decided it needed my SSH keys.

It runs as my uid — so nothing stood between it and ~/.ssh but its own judgment. That's not a boundary, that's a vibe.

First fix

Bubblewrap: a sandbox you assemble yourself

bwrap builds a sandbox out of Linux namespaces — fresh mount, pid, user and network views for one process, no root daemon. It's the layer under Flatpak.

What it buys you

No daemon, no root — it's just a process
Bind in exactly the paths you choose
Mask the rest — ~/.ssh simply isn't there

What it costs you

The boundary is a flag list you maintain
One missing --bind is a hole in the wall
Real agent tooling needs so many holes it turns to Swiss cheese
Going ephemeral

A container per session

The wrapper became a wall: systemd-nspawn containers, grabbed from a four-slot pool per session. Only the repo I'm working on gets bind-mounted in; on exit the root filesystem is discarded.

What it buys you

A full OS inside — tools just work
The boundary is the container, not a rule list
Ephemeral by default: every session starts clean

What it costs you

Shares the host's network namespace
Agent uid = my uid, so mounted files stay writable
One terminal, one session — and Linux only…
The wall

It doesn't work on a Mac

systemd-nspawn is Linux namespaces all the way down. macOS has none of it. Half my life is on a MacBook.

Stop bringing the sandbox to the machine.
Put the agent on a machine that is the sandbox.

The pivot

A box built to contain it

redtruck, a NixOS server, grows a persistent container: the devbox. The agent inside runs as uid 1500 — deliberately outside the host's uid range — on its own private veth network.

SSH, sops and signing keys stay on the host. Secrets enter only as read-only bind mounts under /run/secrets.

Blast radius

Scope the token

The agent has to push code — but a classic PAT is keys-to-everything. Each box gets a fine-grained PAT scoped to an explicit repo allowlist, and a branch-protection ruleset guards what even that token can do.

The box holds a scoped key.
GitHub holds the code.

The front door

Paseo: plan anywhere, code in the box

Inside the box, the paseo daemon listens on 127.0.0.1:6767. The only way in is tailscale serve — one door, published to my tailnet, password required.

Laptop, Mac, even my phone are thin clients. Each session gets its own git worktree inside the box. I plan with Claude from anywhere; the code never leaves.

New problem

One box, two lives

Work repos and personal repos now share a filesystem — and a token. Whatever one project can reach, every project can reach.

That's cross-contamination waiting for a prompt injection.

Multi-instance

Workbox: isolation between lives

The container module went multi-instance. workbox is a second box with its own GitHub token — a different allowlist — and its own signing key, so a commit's signature says which box made it.

Personal and work can no longer touch.

Scoreboard

What each boundary bought

Four eras, five dimensions.

Now

Keys on the host. Repos in the box. Code on GitHub.

Two containers on redtruck, each with one scoped credential and one signing identity. Paseo serves each box to the tailnet; I plan with Claude from wherever I am, and nothing the agent does can reach past its wall.

This presentation was planned in that setup.
