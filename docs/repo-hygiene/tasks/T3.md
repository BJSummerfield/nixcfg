`invariant: drvPath` — deleting docs and one .gitignore line cannot change a
build. If a drvPath moves, you deleted something load-bearing.

## The decision, already made

and drop `/.superpowers/` from `.gitignore`. Git history is the archive.

Why (rubric D1/D3/D4):

- `.gitignore`'s `/.superpowers/` is dead weight once the tool is gone.

## Your job is the verification, not the deletion
`git rm -r` is the easy part. The task is proving the deletion is safe:

1. **Nothing links to a deleted path.** `grep -rn` for `superpowers`,
   `local-llm-review`, and any filename inside either directory, across the
   whole repo including `README.md`, `docs/new-host.md`, `modules/`, `hosts/`,
   `.github/`, and `ci/`. `docs/repo-hygiene/` may reference them (LEDGER.md and
   STATE.json do) — that directory is itself deleted at T12, so those are fine,
   but list them so the T12 sweep is not surprised.
2. **No operational fact lives only there.** This is the judgement call and the
   reason this task gets a careful reviewer. Read both directories. For every
   fact that looks like operational knowledge — a tuning number, a workaround,
   a "this fails unless you X" — check whether it also exists in a module
   comment, a commit message body, `docs/repo-hygiene/LEDGER.md`, or the
   README. **If something exists only in these docs and is still true, do not
   delete it silently.** Surface it in your summary with the file and the fact,
   and leave the file in place pending a decision. Deleting a superseded claim
   is the point of the task; deleting the only copy of a live fact is a bug.
   Note: the user has decided that operational knowledge worth keeping lives in
   `docs/`, so "relocate it" is an available answer, not just keep-or-delete.
3. **The `.gitignore` line.** Confirm `.superpowers/` is not still produced by
   anything (check `modules/pi-coding-agent/`, `modules/devbox/`, and the agent
   config files) before removing the ignore. If something still writes that
   directory, removing the line means it starts showing up in `git status`.
