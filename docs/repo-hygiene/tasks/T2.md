# T2 — Root README + New_Host relocation

`invariant: drvPath` — pure addition and a doc move. Nothing under `modules/`,
`hosts/`, `flake.nix`, `checks/` or `packages/` may change.

## Why
Rubric C1: a reader should learn what this is, which hosts exist, how to build,
deploy, add a host and rotate a secret, without reading the tree. Rubric C5:
docs live under `docs/`, not the repo root. There is no README today and
`New_Host.md` (341 lines) sits at the root.

## Scope
- **Create** `README.md`.
- **Move** `New_Host.md` -> `docs/new-host.md` (use `git mv`), trim it against
  the README so the two do not restate each other, and link both ways.
- Nothing else.

## What the README must contain
Write for someone who has not seen the repo. Short beats complete.
1. **What this is** — one paragraph. A NixOS/nix-darwin flake configuring five
   Linux hosts and one Mac.
2. **Host table** — name, platform, role, one line each. Source them from
   `flake.nix`'s `nixosConfigurations`/`darwinConfigurations` and the host
   files; do not guess a role, read it. Note that elitebook is headless
   (it enables no graphical modules) if that is still true when you check.
3. **Build and deploy** — the actual commands, verified against
   `.github/workflows/check.yml`, `devshell.nix` and `docs/new-host.md`. Do not
   invent a deploy command that nobody runs. If deployment is
   `nixos-rebuild switch --flake .#<host>`, say so; if there is a wrapper, use it.
4. **The option namespace** — this is the part a reader most needs and cannot
   derive. Three tiers, and they are not obvious:
   - `mine.system.*` — per-machine system policy, set in `hosts/<host>/default.nix`.
   - `mine.accounts.*` — the account registry (uid, password hash, ssh keys,
     NAS access), declared in `modules/users/nixos.nix`, populated by `users/*.nix`,
     opted into by a host importing that file.
   - `mine.user.*` — per-user home-manager config, set inside
     `home-manager.users.<name>` in a host file. ~45 modules declare into it.
   **Note:** T4 performs the `mine.users.*` -> `mine.accounts.*` rename and has
   not run yet. Write the README against `mine.accounts.*` and add a single
   line saying the rename lands in T4, OR write `mine.users.*` and leave T4 to
   update it — pick one, say which in your summary, and be consistent. Do not
   silently describe a namespace that does not exist yet.
5. **Secret rotation** — how sops-nix is used here: where the keys live, the
   per-host `secrets/hosts/<host>.yaml` layout, and the actual rotation
   command. Read `modules/` and `hosts/` for the real shape; `hosts/redtruck`
   currently carries a long sops rationale block that is good source material
   (T8 moves it out of the host later, so do not duplicate it verbatim — link
   or summarize).
6. **How to add a host** — three or four lines, then link to `docs/new-host.md`.
7. **Checks** — `nix flake check` runs host evals, package builds, statix,
   deadnix and formatting. One line, plus how to run the formatter.

## Rules
- **Every command you write must be one you verified exists.** A README that
  documents a command nobody runs is worse than no README. Where you cannot
  verify, say so in your summary rather than guessing.
- Rubric A applies to prose too: no restating what the code says, no history.
- Rubric D2: `docs/new-host.md` gets a title and a date-or-status line saying
  what it is and when it was true.
- Do not document the repo-hygiene effort. `docs/repo-hygiene/` is deleted at
  T12 and the README outlives it.

## Acceptance
1. drvPath loop byte-identical to `docs/repo-hygiene/DRVPATH-BASELINE.txt`
   (compare with `diff <(loop) <(grep -v '^# ' ...)`). This should be trivially
   true; if it is not, you edited something you should not have.
2. `nix flake check` green — the formatter check covers `.md`? Confirm whether
   treefmt formats markdown in this repo; if it does, your files must pass it.
3. No file outside `README.md`, `docs/new-host.md`, and the deleted
   `New_Host.md` is modified. `git diff --stat` proves it.
4. Every command in the README traced to where it is defined or used. List the
   traces in your summary.
5. `New_Host.md` no longer exists at the root and nothing links to the old path
   (`grep -rn 'New_Host' .` comes back clean except in `docs/repo-hygiene/`).
