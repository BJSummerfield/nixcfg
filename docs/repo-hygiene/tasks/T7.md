# T7 — Make the overloaded files do less

`invariant: drvPath` — **every part of this task is a move.** All 15 outputs
byte-identical. This is the highest-risk task in the plan because it is the only
one that relocates code rather than text, and the invariant is the entire
safety net. If a drvPath moves, you changed behaviour; stop and report it rather
than re-recording the baseline.

## The rule
Rubric B: a file has one reason to exist. When a file fails, **the fix is to
make it do less, not to cut it in half at an arbitrary line.** Move the foreign
responsibility to where it belongs, or give it its own file named after what it
actually is. Act only on files the ledger marked *overloaded*.

## 1. `modules/devbox/container.nix` (335 lines) — the main one
TW's verdict: overloaded, with two named destinations.
- **Agent tooling** — `piWrapped`, `ghWrapped`, `claudeSettings`, `agentPkgs`
  and friends in the `let` block → `modules/devbox/agents.nix`, **which already
  exists for exactly this** (31 lines today).
- **The inline `home-manager.users.agent` block** (~90 lines) → a new
  `modules/devbox/home.nix`, matching the split convention this module already
  uses for everything else.

What should remain in `container.nix` is the container definition itself: the
nspawn config, bind mounts, networking. One reason to exist.

Watch: `container.nix` imports `modules/pi-coding-agent/home.nix` directly (not
via an aggregator) — that is deliberate, TW confirmed it. Preserve it.

## 2. `modules/users/nixos.nix` (136 lines)
TW's verdict: overloaded — it declares user accounts **and** wires home-manager.
Two jobs. Move the home-manager wiring to a sibling (`modules/users/home-manager.nix`
or similar). TW hedged on the exact split point; use your judgement and state it.

Note T4 renamed this namespace to `mine.accounts.*`. Do not reintroduce
`mine.users`.

## 3. `hosts/elitebook/default.nix`
TW's verdict: overloaded, destination `modules/pipewire/nixos.nix` as a
suboption mirroring the existing `sample-switch` pattern at :12-13. Small.

## 4. Container address registry — user decision, see `tasks/T7-ip-registry.md`
Read that file; it has the full table and the reasoning. Summary: eleven modules
hardcode a `192.168.100.x` pair, there is no registry, and
`modules/devbox/nixos.nix`'s uniqueness assertion covers only devbox instances —
a collision elsewhere produces a container that starts cleanly and cannot route.

**Keep every current address exactly as it is.** This is a move of where the
numbers are declared, not a renumbering. Generalise the assertion to cover every
container address on a host, and keep its existing comment — it explains the
failure mode better than a new one would.

## Order and safety
Do these as **separate commits**, invariant-checked after each one. If the
invariant breaks, you then know which move did it. Do not batch four
restructurings into one commit and discover a hash moved.

Do not do T12's job: `docs/repo-hygiene/` stays until T12 deletes it.
