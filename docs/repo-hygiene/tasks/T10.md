# T10 — Import aggregators

`invariant: drvPath` — reordering or deriving an import list must not change
what any host builds. All 15 outputs byte-identical, same 15 checks.

## The problem, with the walk's evidence
`modules/{nixos,home,darwin,home-darwin}.nix` are hand-maintained import lists.
Rubric C3 wants them consistently ordered, ideally derived, so adding a module
cannot be half-wired.

TW found `modules/nixos.nix` has **three** ordering violations, not the one
FINDINGS.md caught:
- `./devbox/nixos.nix` sits after `./openssh` (belongs between dns-server and docker)
- `./pipewire/nixos.nix` and `./photoform/nixos.nix` are swapped
- `./jellyfin-server` sits before `./jellybox`

The other three aggregators are correctly alphabetized today. Hand-listing has
now demonstrably drifted three times in one file — that is the argument for
deriving rather than a preference.

TW also checked every module directory against the lists and found **no module
missing from its aggregator**. `modules/theme/home.nix` looks orphaned to a
grep but is imported via `home-manager.sharedModules` in `modules/theme/nixos.nix`;
`modules/pi-coding-agent/home.nix` is imported directly by
`modules/devbox/container.nix`. Neither is a defect. Do not "fix" them.

## The choice you own
**Derive from the filesystem** (`lib.filesystem.listFilesRecursive` or a
`readDir` filter) **or keep hand-listed and alphabetize.** PLAN.md calls this a
two-sentence choice, not a research bundle. Decide and justify in one paragraph.

Things that must inform the decision, not be discovered afterwards:
1. **The four aggregators select by filename, not by directory.** `nixos.nix`
   imports `*/nixos.nix`, `home.nix` imports `*/home.nix`, etc. A derived
   version must reproduce exactly that selection.
2. **`modules/theme/home.nix` must NOT be picked up by `modules/home.nix`.** It
   is deliberately imported through `home-manager.sharedModules` instead. A
   naive "import every `*/home.nix`" glob would double-import it. Check what
   happens if you do — a duplicate import may be silently harmless or may be an
   error, and either way the drvPath must not move. This is the single trap in
   this task.
3. Same question for `modules/pi-coding-agent/home.nix`, imported by
   `modules/devbox/container.nix:146`.
4. `modules/alacritty/linux.nix` is imported conditionally into the Linux
   home-manager aggregator only — TW confirmed this is a different axis from
   the `nixos`/`darwin` split, not drift. Whatever you build must preserve it.
5. A derived list evaluates `readDir` at eval time. Confirm that does not make
   the flake impure or change the drvPath.

If deriving cannot reproduce the current selection exactly, **alphabetize by
hand and say why deriving was rejected** — a correct hand-list beats a clever
derivation that changes behaviour. Record the rejection in the PR body.

## Scope
`modules/nixos.nix`, `modules/home.nix`, `modules/darwin.nix`,
`modules/home-darwin.nix`. Nothing else. Do not add, remove or rename a module.
