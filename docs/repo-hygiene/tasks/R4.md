## G1 — internal drift (fix first; newest spelling is the reference)

### 1. Hand-built `${pkg}/bin/x` vs `lib.getExe`/`lib.getExe'`
**Signal:** `grep -rn '\${[a-zA-Z0-9_.'"'"']*}/bin/' modules hosts`
**Reference (already the repo's own newest spelling):** `lib.getExe pkgs.foo`
/ `lib.getExe' pkgs.foo "bin-name"` — 15+ call sites, newest addition
`modules/local-llm/vllm-service.nix:17` (`podman = lib.getExe' pkgs.podman
"podman";`, file added 2026-09-01).
**Divergent, cited:**
- `modules/devbox/container.nix:53` (`real = "${piWrapped}/bin/pi";`) —
  **same file**, 8 lines below `container.nix:45`
  (`real = lib.getExe pkgs.claude-code;`). One file, two spellings.
- `modules/local-llm/nixos.nix:214` (`ExecStart = "${pkgs.podman}/bin/podman
  pull ...";`) vs the same package via `getExe'` in the same module
  directory's newer file, `vllm-service.nix:17` above.
- `modules/swaybg/home.nix:31`, `modules/swayidle/home.nix:11-12,45`
  (brightnessctl/niri/systemctl) and `modules/vikunja-server/nixos.nix:144`
  (pg_dump) — all oldest-generation files (swaybg/swayidle added
  2026-01-05, predates `getExe` becoming the house style).
**Caveat:** `piWrapped` (symlinkJoin) and `photoform` (writeShellApplication)
outputs still expose a single `bin/<pname>`, so `getExe` works on them too —
verify `pname` before converging, don't assume.

### 2. `sops.secrets.<name>` shape: dotted-path vs nested attrset for the
   same secret family in one host file
**Signal:** `grep -n 'sopsFile = ' hosts/*/default.nix | sort | uniq -c`
— look for a host where some secrets use `foo.sopsFile = X;` (one line) and
sibling secrets in the same block use `foo = { sopsFile = X; ... };`.
**Cited:** `hosts/redtruck/default.nix:56` (`devbox-paseo-password.sopsFile
= ../../secrets/hosts/redtruck.yaml;`) vs `hosts/redtruck/default.nix:50-53`
and `:57-61` (nested-attrset form) for the otherwise-identical
`devbox-github-token` / `devbox-signing-key` secrets in the same block.
**Replacement:** pick the nested-attrset form (it's the majority shape,
7 of 8 entries in the same file) for every multi-field secret; this overlaps
T8's host-file diet and rubric F2 — do not duplicate the finding there,
just note it here for TW's per-file pass.

## G2 — external drift (upstream gained something this repo predates)

### 3. Per-secret `sopsFile = ../../secrets/hosts/<host>.yaml` repeated
   on almost every entry vs `sops.defaultSopsFile`
**Signal:** `grep -c 'sopsFile = ' hosts/<host>/default.nix` > 1 with the
same RHS path repeated.
**Cited (old):** `hosts/redtruck/default.nix` — 6 of 7 secrets repeat the
identical `sopsFile = ../../secrets/hosts/redtruck.yaml;`;
`hosts/vps/default.nix:43,51,91` (3 of 4) and
`hosts/paynefield/default.nix:17,25` (2 of 3) do the same for their host
files. `sops.defaultSopsFile` is never set anywhere in this repo
(`grep -rn defaultSopsFile .` → no hits).
**Replacement, verified in the pinned sops-nix source:**
`/nix/store/s154mmk8ahvc71gq8xfkbzlk240yvniv-source/modules/sops/default.nix:203`
declares `sops.defaultSopsFile` (used as `mkOptionDefault` for every secret's
`sopsFile` at line 50). Set once per host (`sops.defaultSopsFile =
../../secrets/hosts/<host>.yaml;`), drop the per-secret line except where a
secret genuinely lives in a different file (e.g. `restic-b2.yaml` — keep the
override only there). Shorter, and a copy-pasted-wrong path can no longer
happen for the common case. Meets G3.

## NOTE-ONLY (recorded, not actioned — fails or is unproven against G3)

### 4. Hand-written INI text (`xdg.configFile.*.text`) vs home-manager's
   native `programs.fuzzel.settings`
**Signal:** a module writing `xdg.configFile."<prog>/<prog>.ini".text =
someString` for a program home-manager itself has a module for.
**Cited (old):** `modules/fuzzel/home.nix:58`
(`xdg.configFile."fuzzel/fuzzel.ini".text = fuzzelCfg;`, hand-built
`[colors]`/`[main]`/`[border]` INI string).
**Upstream (pinned home-manager):**
`/nix/store/qfwgprhswyy0gq5w81x5p0j3qbxs5l1b-source/modules/programs/fuzzel.nix:31,58-59`
— `programs.fuzzel.settings` (freeform, rendered via `iniFormat.generate`)
already exists and would replace the hand-rolled text block with a plain
attrset. Meets G3 on its own (removes hand-rolled INI generation), **but**
this repo's `modules/fuzzel/home.nix` defines its own
`options.mine.user.fuzzel.enable` wrapper around raw `xdg.configFile` rather
than the upstream `programs.fuzzel` option tree at all — converting is a
bigger reshuffle than a spelling swap (option namespace, `programs.fuzzel`
vs `mine.user.fuzzel` moving parts) and its payoff is one file. Record for
T13, do not auto-apply.
Related but explicitly **not** proposed: home-manager's
`wayland.windowManager.niri` module
(`.../modules/services/window-managers/niri.nix`) could in principle replace
`modules/niri/home.nix`'s hand-written `config.kdl`/`binds.kdl`, but that
module also manages niri's systemd units and package — a behavior change,
not an idiom swap. Do not put this on TW's list; it fails G3 outright.
