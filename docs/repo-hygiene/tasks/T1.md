# T1 — Lint and format gate

`invariant: none` (CI and flake checks change by design; no host or package
output may change — see acceptance).

## Why
Rubric E1: correctness is enforced, not remembered. Every later task in this
plan is verified by machine, so the machine has to exist first.

## Scope — edit only these
- `flake.nix` (add `checks.<system>.*`, add tools to the devShell)
- whatever statix/deadnix flag, per the fix list below
- `.github/workflows/check.yml` only if it does not already run `nix flake check`
  in a way that picks the new checks up. Prefer changing nothing here.

## What R1 already settled — do not re-research
Read `tasks/R1.md` first. It ran the tools for real. In particular:

- **nixfmt is already clean**: treefmt reports 0/129 files changed. There is
  **no reformat commit**. PLAN.md called this "the largest blame-noise commit of
  the whole effort" — that premise is dead. Do **not** touch
  `.git-blame-ignore-revs`; do not reformat anything.
- Wire all three as `checks.<system>.*` `runCommand` derivations, not a separate
  CI step, so local `nix flake check` and CI stay the same gate.
- Add `statix` + `deadnix` to the devShell. `nixfmt` is already there.
- Use the repo's existing formatter (`.#formatter`, nixfmt-tree/treefmt). Do not
  introduce a second formatter.

## The fixes
- **statix, fix (~16)**: the `[4]`/`[3]` inherit conversions and the one `[10]`
  empty pattern. R1 cites the sites.
- **statix, exclude, do not hand-edit**: `[20] repeated keys` on
  `hosts/*/hardware-configuration.nix` — these are `nixos-generate-config`
  output and say "Do not modify this file!". Exclude the glob at the check
  invocation.
- **statix `[20]` on `modules/devbox/container.nix:108,148,160,274` and
  `modules/niri/home.nix:30`**: R1 judged these deliberate readability grouping
  and recommends leaving them. You must still make the check pass. Prefer a
  narrow, commented exclusion over merging attrs the author split on purpose —
  and if you do merge them, say so in your summary so the reviewer can judge it.
- **deadnix, fix (~15)**: unused named lambda args in files that also have a
  `...` catch-all, so dropping the name loses nothing. Exclude the same
  generated-file glob.

## Acceptance
1. `nix flake check` green, and it now fails if a file is unformatted or trips
   statix/deadnix. Prove the second half: break one file deliberately, show the
   check fails, revert.
2. Every statix/deadnix finding is either fixed or excluded with a stated
   reason. No finding is silently suppressed by disabling a whole lint.
3. **No build output changes.** T1 is `invariant: none` for *checks*, not for
   hosts and packages: run the full PROCESS drvPath loop before and after and
   show it byte-identical. The statix/deadnix fixes are refactors and must not
   move a single drvPath. This is the strongest acceptance criterion here.
4. Record the resulting drvPath output as the baseline for every later task —
   write it to `docs/repo-hygiene/DRVPATH-BASELINE.txt` and commit it.
5. Note the added wall-clock cost of `nix flake check`, measured, in the summary.

## Out of scope
Comment edits, renames, doc changes, anything under `docs/`. If a linter fix
tempts you into a rewrite, don't — record it and move on.
