## 1. `${pkg}/bin/x` -> `lib.getExe` / `lib.getExe'`
Reference spelling, newest in-repo: `modules/local-llm/vllm-service.nix:17`.
Sites found by R4 and the walk — **verify each still exists before editing**,
T5/T6 have since rewritten some of these files:
- `modules/local-llm/nixos.nix` — `${pkgs.podman}/bin/podman`
- `modules/devbox/container.nix` — `"${piWrapped}/bin/pi"`, while the same file
  already uses `lib.getExe` a few lines above
- `modules/swaybg/home.nix`, `modules/swayidle/home.nix` (several)
- `modules/hyprlax/home.nix`
- `modules/helix/languages/markdown.nix` (`mpls`)

**Three traps — check `meta.mainProgram` before converting each:**
- `piWrapped` is a `symlinkJoin` named `pi-wrapped` with **no** `mainProgram`,
  so naive `lib.getExe` resolves to `pi-wrapped` and breaks. Either add
  `meta.mainProgram = "pi"` (pattern: `modules/photoform/package.nix`,
  `modules/encode_queue/package.nix`) or use `getExe' piWrapped "pi"`.
- `swaylock-effects`: binary name diverges from the package attr.
- `mpls`: unverified — check the derivation, not the attr name.
Where `mainProgram` is absent or wrong, prefer `getExe' pkg "binname"`, which
is explicit and cannot silently resolve to the wrong thing.
`modules/polkit-kde/home.nix` uses `/libexec/`, not `/bin/` — out of scope.

## 2. sops: one shape per host, and `defaultSopsFile`
- `hosts/redtruck/default.nix` mixes dotted (`foo.sopsFile = X;`) and nested
  (`foo = { ... };`) for sibling secrets. Converge on nested (the majority).
- `sops.defaultSopsFile` is **set nowhere in the repo**, while hosts repeat an
  identical path: redtruck 6/6, vps 3/4, paynefield 2/3 (counts verified by TW,
  correcting R4's 6/7). Set it once per host, drop the repeated per-secret line,
  keep an explicit `sopsFile` only where a secret genuinely lives elsewhere
  (e.g. `restic-b2.yaml`). Shorter and typo-proof — clears G3.
- This overlaps T8. Do the sops shape work **here**; leave the rationale-essay
  relocation and the generated-secrets question to T8.

## 3. disko `/dev/nvme0n1` -> `/dev/disk/by-id/...` — FLAGGED, decide and report
redtruck (newest) uses stable by-id paths; `hosts/elitebook/disko.nix` and
`hosts/t495/disko.nix` still use `/dev/nvme0n1`, which survives nothing if
devices renumber. Clears G3 on merit.

**But it will almost certainly move those two hosts' drvPaths**, because the
device path is part of the config. Disko describes partitioning, so the change
affects a reinstall rather than a running system — but the hash moves.

Do it, measure it, and **report the drvPath delta separately** from the rest of
the task. If elitebook and t495 move and nothing else does, that is the expected
result and the baseline gets re-recorded. If anything *else* moves, stop and say
so. Do not silently fold this into the invariant.

You need the real by-id paths for those two machines. If you cannot obtain them
(they are not this host), **do not invent them** — skip item 3, say so, and
leave it for someone with the hardware. A wrong by-id path is an unbootable
machine.
