## The rule being applied
Rubric B8: **a host file declares policy — which options, which values.**
Implementation, repetition, and rationale belong in the module the host is
enabling. A host file that explains *how* something works has taken on a
module's job.

## 1. redtruck's sops essay (~lines 16-49)
Thirty-odd lines explaining the devbox secret contract: why `github-token` is
0440 group `users` (the agent runs as uid 1500 and sops-nix's `owner` takes a
host username), why `paseo-password` is root-only (read by PID 1 before dropping
to `User=agent`), why `signing-key` is 0400 uid 1500 (`ssh-keygen -Y sign`
ignores any key a group bit can reach), that each container gets its own key so
a signature identifies the box, and that rotation needs
`systemctl restart container@<name>`.

**This is real operational knowledge and none of it may be lost.** But it
describes a contract that `modules/devbox/nixos.nix` owns and enforces — the
host merely opts in. Move it there, next to the option declarations or the
bind-mount code it explains, whichever puts each fact adjacent to the thing it
constrains. The host keeps at most a one-line pointer.

The walk's suggestion: `modules/devbox/nixos.nix` already documents the uid/mode
contract per field in its option `description`s, so much of this may belong in
those descriptions rather than as comments.

## 2. Can the devbox module generate its own secrets?
The six declarations follow one shape per container. `modules/devbox/nixos.nix`
already has the `devboxes` attrset, and `mapAttrsToList` over it elsewhere.
Consider generating `sops.secrets.<name>-{github-token,paseo-password,signing-key}`
from that attrset so a host declares only which devboxes exist.

**Judge it, do not assume it.** Generating is better only if it removes
repetition without hiding the contract. If a reader can no longer see what
secrets a host has without reading the module, that is a real cost — say so and
leave the declarations. Either answer is acceptable; an unjustified one is not.

If you do generate: the drvPath must not move, which is the proof it is a pure
move.
